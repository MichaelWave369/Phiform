# Executed KTX2 / Basis Encoding — Rung 10

Rung 10 advances PhiForm from a compression **plan** to real encoder output.

The authority boundary is:

```text
audited Three.js texture
        |
        v
browser-normalized PNG
        |
        +-- SHA-256
        +-- role-derived sRGB / linear semantics
        |
        v
localhost bridge
        |
        v
operator-installed Khronos KTX Software
        |
        +-- ktx create
        +-- BasisLZ / ETC1S OR UASTC LDR 4x4
        +-- mip generation
        |
        v
KTX2 bytes
        |
        +-- KTX2 identifier check
        +-- bridge SHA-256
        |
        v
browser fetch
        |
        +-- byte-length verification
        +-- KTX2 identifier verification
        +-- independent SHA-256
        |
        v
phiform.texture-encode-receipt.v1
```

## Why PhiForm does not use Three's KTX2Exporter for compression

Three.js ships `KTX2Exporter`, but that exporter writes KTX2 containers from texture data. It does not perform Basis Universal ETC1S/UASTC encoding.

PhiForm therefore delegates actual Basis encoding to Khronos KTX Software.

Official references:

- https://github.khronos.org/KTX-Software/ktxtools/ktx_create.html
- https://github.khronos.org/KTX-Software/ktxtools/ktx_encode.html
- https://www.khronos.org/ktx/
- https://threejs.org/docs/pages/KTX2Loader.html
- https://threejs.org/docs/pages/KTX2Exporter.html

## Install / configure on Windows

Install Khronos KTX Software using an official release or package appropriate for your machine.

Confirm the unified CLI works:

```powershell
ktx --version
```

If `ktx.exe` is not on PATH, point PhiForm at it before starting the bridge:

```powershell
$env:PHIFORM_KTX_BIN = "C:\path\to\ktx.exe"
npm run bridge
```

The bridge probes:

```text
ktx --version
```

The PhiForm texture panel reports ONLINE only when that probe succeeds.

## Browser source normalization

Rung 10 currently executes compression only for **8-bit LDR textures**.

The loaded Three.js texture is copied through browser canvas into a normalized RGBA PNG.

PhiForm refuses float/HDR textures instead of silently reducing their precision.

The receipt stores:

- texture ID
- texture name
- audited PBR roles
- normalized PNG SHA-256
- normalized PNG byte length
- selected Basis codec
- returned KTX2 SHA-256
- returned KTX2 byte length
- browser hash-verification status

The PNG baseline is a browser-normalized source, not necessarily the original PNG/JPEG bytes that were embedded in the GLB.

## Transfer-function policy

The texture audit determines one expected transfer interpretation.

Color roles:

```text
base color
emissive
    -> sRGB
```

Data roles:

```text
normal
roughness
metalness
occlusion
alpha
bump
displacement
light
    -> linear
```

A texture whose roles require both interpretations is already a Rung 9 FAIL and cannot execute in Rung 10.

## ETC1S / BasisLZ path

PhiForm currently requests the equivalent of:

```text
ktx create
  --format R8G8B8A8_{SRGB|UNORM}
  --assign-tf {srgb|linear}
  --generate-mipmap
  --mipmap-filter lanczos4
  --fail-on-origin-changes
  --encode basis-lz
  --qlevel 128
  --clevel 2
  --threads 1
  source.png
  encoded.ktx2
```

Rung 9 maps ordinary color/scalar delivery textures to this path.

## UASTC path

For normal, bump, and displacement detail, PhiForm currently requests:

```text
ktx create
  --format R8G8B8A8_UNORM
  --assign-tf linear
  --generate-mipmap
  --mipmap-filter lanczos4
  --fail-on-origin-changes
  --encode uastc-ldr-4x4
  --uastc-quality 2
  --uastc-rdo
  --uastc-rdo-l 0.5
  --uastc-rdo-m
  --zstd 18
  --threads 1
  source.png
  encoded.ktx2
```

This keeps the encoder choice explicit and receiptable.

## Receipt semantics

Successful execution emits:

```text
phiform.texture-encode-receipt.v1
```

The receipt can only be created after every texture in the batch succeeds.

It records:

- source artifact ID
- exact edit-graph node
- texture policy
- encoder ID + reported version
- every source PNG hash/size
- every output KTX2 hash/size
- codec per texture
- source-PNG / output-KTX2 byte ratio
- independent browser hash verification
- `compressionExecuted: true`
- `allOutputsValidated: true`

## Cross-platform determinism

Khronos notes that Basis Universal encoding output may differ bit-for-bit across platforms, even when outputs are visually equivalent and valid.

PhiForm therefore does **not** claim universal deterministic KTX2 bytes.

Instead, each receipt binds the exact bytes generated by that execution.

The UASTC path also disables RDO multithreading and requests one encoder thread to reduce avoidable run-to-run variation, but the receipt remains byte-specific.

## What Rung 10 still does not claim

Rung 10 does not yet:

- rewrite the source GLB
- create `KHR_texture_basisu` texture references
- replace material texture bindings
- encode HDR/float textures
- prove normal-map mip quality
- perform visual error metrics against the source
- create engine-native texture assets

The next texture integration rung should produce a **derived GLB** whose verified KTX2 textures are actually bound into its glTF material graph.

## CI qualification

`npm run texture:encode:contract` starts the real PhiForm local bridge with a fake CLI process that implements the same process contract.

The fixture verifies:

- encoder probing and version reporting
- ETC1S / BasisLZ arguments
- UASTC + RDO + Zstd arguments
- sRGB / linear format selection
- mipmap-generation request
- async texture-job lifecycle
- KTX2 output identifier validation
- SHA-256 artifact binding
- source-hash mismatch rejection

CI does **not** claim a real Basis codec run. Real execution requires operator-installed Khronos KTX Software.


## Rung 11 binding handoff

Rung 10 proves standalone KTX2 bytes.

Rung 11 may consume those exact in-session bytes to derive a fallback-bearing GLB using `KHR_texture_basisu`.

The Rung 10 receipt remains the encoder evidence. Rung 11 creates a separate derived-artifact receipt binding those KTX2 hashes to specific glTF texture objects.

See [KHR_texture_basisu Derived GLB](BASISU_GLB.md).
